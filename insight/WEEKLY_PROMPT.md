# Weekly Deep Insight — คำสั่งสำหรับ scheduled task

> ไฟล์นี้คือ "prompt" ของงานเขียนรายสัปดาห์ · scheduled task บน claude.ai/code/routines
> ถูกตั้งให้อ่านไฟล์นี้แล้วทำตาม · แก้วิธีเขียนที่นี่ ไม่ต้องแก้ใน task

## งาน

1. หาไฟล์ใหม่สุดใน `insight/data/` (ชื่อไฟล์ = วันที่ซื้อขายสุดท้ายของสัปดาห์ เช่น `2026-10-23.json`)
   ถ้าวันที่ในชื่อไฟล์เก่ากว่าวันที่รันเกิน 6 วัน → หยุด ไม่ต้องเขียนอะไร
2. **ตรวจข้อมูลก่อนใช้:** ถ้า `generated_at` (เวลาไทย) เร็วกว่า 04:00 น. ของวันถัดจากวันที่ในชื่อไฟล์
   แปลว่าดึงก่อนตลาดสหรัฐปิด → แท่งสุดท้ายเป็นราคาระหว่างวัน ให้เขียนเตือนบรรทัดแรกใต้หัวข้อ
   ถ้าเจอตัวเลขที่ดูผิดปกติ (เช่น ขยับเกินจริง, ค่าว่าง) ให้ระบุในส่วนแหล่งข้อมูล อย่าใช้ตัวนั้นสรุป
3. ถ้า `insight/weekly/` มีไฟล์ → อ่าน 2 ฉบับล่าสุดไว้ทำ Scorecard · ถ้าว่าง → เป็นฉบับแรก ข้าม Scorecard
4. ค้นเว็บหาเรื่องสำคัญของสัปดาห์: ตัวจุดชนวนของการเคลื่อนไหวใหญ่, งบบริษัทใหญ่, ตัวเลขเศรษฐกิจ,
   Fed/ธนาคารกลาง, ภูมิรัฐศาสตร์, flow/positioning ของกองทุน, และปฏิทินสัปดาห์หน้า
   - เริ่มจากสรุปตลาดรายวัน/รายสัปดาห์ของ CNBC, Reuters, Yahoo Finance, Bloomberg (เท่าที่อ่านได้) ก่อน แล้วค่อยเจาะ
   - งบค้นประมาณ 10–15 ครั้ง · พอได้คำอธิบายของการเคลื่อนไหวใหญ่ทุกตัวแล้วให้หยุด
   - วันประกาศงบ/ตัวเลขที่ยังไม่มีบริษัทหรือหน่วยงานยืนยัน ให้ใส่ 🚩 "ยังไม่ยืนยัน"
5. เขียน `insight/weekly/<วันที่เดียวกับไฟล์ data>.md` ตามวิธีคิดและรูปแบบข้างล่าง
6. `git add insight/weekly/<ไฟล์นั้น>.md && git commit -m "weekly insight <วันที่>" && git push origin HEAD:main`
   (push เข้า main ตรง เพื่อให้เว็บอัปเดตเอง — add เฉพาะไฟล์ที่เพิ่งเขียน ห้ามแตะไฟล์อื่น)

## ผู้อ่าน

นักลงทุนรายย่อยชาวไทยที่ถือหุ้นสหรัฐ ETF และคริปโต อ่านสัปดาห์ละครั้ง อยากเข้าใจ "ภาพใหญ่ที่ปะติดปะต่อกัน"
ไม่ใช่สรุปข่าว สิ่งที่ต้องการคือ insight: สิ่งที่ตัวเลขบอกแต่หัวข่าวไม่ได้บอก, เรื่องต่างๆ เชื่อมกันยังไง,
และมันแปลว่าอะไรต่อจากนี้

## วิธีคิด (ทำตามลำดับ)

1. **หาธีมเดียวของสัปดาห์** — ถ้าต้องอธิบายสัปดาห์นี้ด้วยประโยคเดียว คืออะไร ทุกส่วนข้างล่างต้องโยงกลับมาที่ธีมนี้
2. **ต่อจุด (connect the dots)** — เขียนเป็นห่วงโซ่เหตุและผล เช่น
   น้ำมัน → ความคาดหวังเงินเฟ้อ (T10YIE) → ยีลด์ → valuation หุ้นเทค → rotation ไปกลุ่มตั้งรับ
   แต่ละข้อต่อต้องมีตัวเลขรองรับ ข้อต่อไหนยังไม่มีหลักฐาน ให้เขียนว่า "ยังเป็นสมมติฐาน"
3. **เศรษฐกิจจริง vs ตลาด** — ใช้ `economy` (FRED) ดูว่าเศรษฐกิจจริง (เงินเฟ้อ, จ้างงาน, credit spread,
   financial conditions) กับสิ่งที่ตลาดกำลัง price สอดคล้องหรือขัดกัน
4. **ไส้ใน vs หน้าฉาก** — breadth, RSP/SPY, sector, megacaps, MOVE vs VIX และ `flags`
   (flags คือรายการความขัดแย้งที่โค้ดจับได้อัตโนมัติด้วยกฎตายตัว อาจถูกครึ่งเดียว —
   ให้ตัดสินทีละข้อว่า สำคัญ / ถูกครึ่งเดียว / ไม่สำคัญ พร้อมเหตุผล และเพิ่มความขัดแย้งที่โค้ดไม่ได้จับเองได้)
5. **ตลาดเชื่ออะไรอยู่ แล้วอะไรจะทำให้ความเชื่อนั้นพัง** — ระบุ consensus แล้วหาสิ่งที่จะหักล้างมัน
6. **ระดับราคาแบบมีเงื่อนไข** — จาก MA, swing lows/highs, RSI ใน snapshot: "ถ้า X ปิดหลุด Y แปลว่า Z"
7. **Scorecard** — เทียบกับบทวิเคราะห์ฉบับก่อน: อะไรที่บอกไว้แล้วเกิดจริง อะไรผิด พูดตรงๆ ว่าผิดเพราะอะไร

## กฎ

- ตัวเลขตลาดและเศรษฐกิจต้องมาจาก snapshot หรือแหล่งที่ค้นเจอ ห้ามเดา ห้ามใช้ความจำ
  - ตัวเลขจาก snapshot ไม่ต้องอ้างในประโยค (ระบุรวมครั้งเดียวในส่วนแหล่งข้อมูล)
  - ตัวเลขจากเว็บให้ใส่ชื่อแหล่งสั้นๆ ในวงเล็บ เช่น (Reuters) · ถ้าเห็นแค่ในสรุปผลค้นหา ไม่ได้เปิดอ่านหน้าจริง ให้ใส่ 🚩
- ถ้าตัวเลขใน snapshot กับข่าวต่างกัน ให้ใช้ snapshot เป็นหลัก แล้วบอกเหตุผลถ้ารู้
  (เช่น CL=F/BZ=F คือสัญญาเดือนใกล้สุด ข่าวอาจอ้างสัญญาเดือนอื่น)
- ข้อมูลเศรษฐกิจแต่ละชุดออกไม่พร้อมกัน — บอกเดือนของตัวเลขทุกครั้ง (เช่น "core PCE เดือน ส.ค.")
- ระดับราคาใช้ `ma*` / `swing_lows_6m` / `swing_highs_6m` (swing = ราคาระหว่างวัน) · `high_1y` / `low_1y` คือราคาปิด
- `change_unit = "points"` คือเปลี่ยนเป็นจุด (ยีลด์ 0.042 = 4.2 bps) ไม่ใช่ %
- เวลาในปฏิทินให้ใส่เวลาไทยเสมอ
- แยกให้ชัดว่าอะไรคือข้อเท็จจริง อะไรคือการตีความ
- ภาษาไทย ใช้ศัพท์อังกฤษได้ แต่ศัพท์เทคนิคครั้งแรกต้องอธิบายสั้นๆ ในวงเล็บ
- ไม่บอกให้ซื้อหรือขาย ให้ระดับที่ต้องจับตาและเงื่อนไขแทน
- ลึกแต่ไม่ยืด ประมาณ 5,000–8,000 ตัวอักษร (อ่านจบใน ~10 นาที) ทุกย่อหน้าต้องมีข้อมูลใหม่ ห้ามพูดซ้ำ
